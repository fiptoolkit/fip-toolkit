🔬 Simulateur Go2Econtact

Testez vos règles d'accusés de réception avant de les déployer

📬 Règle par défaut

Tous les emails reçoivent un AR, SAUF votre organisation/association/service et les exclusions configurées ci-dessous.

Les inclusions servent à forcer l'envoi d'AR pour des exceptions spécifiques (ex: un email interne qui doit quand même recevoir un AR).

📂 Importer une configuration

Importez directement un fichier JSON exporté depuis le wizard Go2Econtact pour tester votre configuration.

💡 Fichier au format Go2Econtact-wizard-config-*.json

📧 Domaine interne

Le domaine de votre organisation. Les emails de ce domaine ne recevront pas d'AR par défaut.

💡 Utilisez *. pour inclure tous les sous-domaines

🚫 Exclusions (ne recevront JAMAIS d'AR)

🌐 Domaines à exclure

Bloquez tous les emails d'un domaine complet (ex: publicite.fr)

💡 Vous pouvez utiliser *. pour exclure tous les sous-domaines

✉️ Adresses spécifiques à exclure

Bloquez des adresses email précises (ex: robot@exemple.com)

🔍 Patterns automatiques à exclure

Bloquez des types d'emails automatiques (ex: tous les noreply@*)

💡 Utilisez * comme joker (ex: noreply@* bloque tous les noreply)

📝 Sujets à exclure

Bloquez les emails selon leur objet. Utilisez les préfixes [COMMENCE], [CONTIENT] ou [FINIT] (ex: [COMMENCE]Re: exclut toutes les réponses).

💡 [COMMENCE]texte · [CONTIENT]texte · [FINIT]texte — insensible à la casse

⭐ Inclusions (recevront TOUJOURS un AR)

⚠️ Important : Les inclusions ont la priorité ABSOLUE. Elles annulent toutes les autres règles (exclusions, domaine interne, patterns).

✉️ Adresses qui recevront TOUJOURS un AR

Ces adresses recevront un AR même si elles sont dans les exclusions ou le domaine interne

🌐 Domaines qui recevront TOUJOURS un AR

Tous les emails de ces domaines recevront un AR
